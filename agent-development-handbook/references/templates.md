编号不是必须的，但写了方便在对话和提交信息里引用。每条尽量带验收条件。开工时先把条目挪进「进行中」再动手；停下就退回「待办」或转「阻塞」。按阶段分组时，阶段内自上而下做，别跳到下一阶段去做更顺手的。

`- [x]` 只表示「做完了、待搬走」，不是完成态：完成 = 删掉这行；有用户可感知变化时再进 CHANGELOG。纯内部改动（重构、补测试）不进 CHANGELOG，靠 commit message 留痕。

## CHANGELOG.md

````markdown
# Changelog

本项目遵循 [Keep a Changelog](https://keepachangelog.com/zh-CN/1.1.0/)，版本号遵循 SemVer。

## [Unreleased]

### Added

- 手机端设置页全屏，导航改为横向标签

### Fixed

- 深色模式下二维码对比度不足

## [0.0.2] - 2026-10-26

### Added

- 初版：局域网手机访问、密码登录、二维码
````

写「用户看到的变化」，不写「重构了 XxxService」。用不到的类别不要留空标题；Keep a Changelog 的六类是 `Added / Changed / Deprecated / Removed / Fixed / Security`，中文等价写法是 `新增 / 变更 / 弃用 / 移除 / 修复 / 安全`——一旦选了中文就整份文件都用中文，且仓库里有按英文标题解析的工具时不要选中文。

## .gitignore

放仓库根并提交（`~/.gitignore` 只影响本机）。下面摘自 [github/gitignore](https://github.com/github/gitignore) 的常见条目，按项目删改、别整段照抄；完整清单看仓库根目录里的语言模板和 `Global/` 下的系统 / 编辑器模板。

````gitignore
# 构建产物
build/
dist/
target/
out/
node_modules/

# 本地环境
.env
.env.*
!.env.example

# 凭据与私钥（能挡新增文件，挡不住已推送的历史）
*.pem
*.p12
*.keystore
credentials.*

# 系统与编辑器
.DS_Store
Thumbs.db
*.swp
.idea/
.vscode/

# 日志与临时
*.log
tmp/
````

- 只防「以后再提交」：已经进过暂存区或历史的文件归 `git rm --cached` 管，那是 git 写操作，先问用户。
- 凭据删掉不等于没泄露：推送过的密钥要换，`filter-branch` / `git filter-repo` 会改写历史，更要先问。
- 生成物目录名随技术栈变（`build/`、`dist/`、`target/`、`.next/`、`Pods/`），照项目实际的补。
